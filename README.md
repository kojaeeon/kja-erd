# KJA ERD

개인용 로컬 ERD 편집기. Node.js 24.10 이상이 필요합니다.

```powershell
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:3000 접속. 서버는 로컬 주소에만 바인딩합니다.

상단 `메뉴`는 프로젝트 메뉴입니다. `테이블 표시 옵션`에서 PK·자동증가·FK·NULL·논리명·물리명·타입·UNIQUE·기본값을 프로젝트별로 표시하거나 숨길 수 있습니다. 변경은 즉시 적용·자동 저장되며 실행 취소가 가능합니다. 논리명 또는 물리명 중 하나는 유지합니다. 표시를 숨겨도 설계 값과 관계선, SQL·엑셀 출력은 유지됩니다. AI 표시는 자동증가로 변경했습니다.

프로젝트 메뉴와 프로젝트 목록에서 복사·삭제할 수 있습니다. 복사는 현재 설계·사전·관계·인덱스·메모·표시 설정을 새 프로젝트 ID로 복사하고 복사본으로 전환합니다. 저장 이력은 복사본에서 새로 시작합니다. 삭제는 휴지통 이동이며 기존 설계와 이력을 보관합니다. `프로젝트 → 휴지통 → 복원`으로 되돌릴 수 있습니다. 현재 프로젝트를 삭제하면 다른 저장 프로젝트 또는 새 프로젝트로 전환합니다. 휴지통 프로젝트는 자동 저장으로 다시 생성되지 않습니다.

새 프로젝트와 블로그 예제의 SQL 기본 대상은 DB2입니다. 상단 DBMS 선택 또는 SQL 팝업에서 대상을 바꿀 수 있으며 기존 프로젝트의 설정은 유지합니다. 테이블 하단 `메뉴 → SQL OUT · 이 테이블`은 해당 테이블의 생성문·PK/FK·인덱스만 출력하고 다운로드 파일명은 `<테이블명>.<DBMS>.sql`입니다. 상단 SQL은 전체 설계를 출력합니다. 다른 테이블을 참조하는 FK는 참조 테이블이 미리 존재해야 합니다.

SQL OUT의 `FK 생성문 포함`은 기본적으로 꺼져 있습니다. 끄면 ERD의 관계선과 컬럼을 유지하면서 출력 SQL의 FOREIGN KEY 및 FK용 ALTER TABLE을 제외합니다. PK·UNIQUE·인덱스 등은 그대로 출력합니다. 옵션이 꺼져 있으면 FK 참조 테이블 사전 생성 안내와 물리 FK 검증도 제외합니다. 전체/개별 테이블 SQL과 모든 DBMS에 적용되며 브라우저에 선택을 기억합니다. 옵션을 변경하면 현재 스크립트를 설계에서 다시 생성하므로 직접 편집한 SQL은 덮어씁니다. 불러온 SQL 파일을 자동으로 분석하여 FK를 제거하는 기능은 아닙니다.

DB2 SQL은 Db2 LUW 11.5 기준으로 IDENTITY, PK/FK/UNIQUE, 기본값, 인덱스, 논리명 COMMENT를 출력합니다. 테이블과 인덱스를 만든 후 ALTER TABLE로 FK를 추가하여 관계 순서와 순환 참조에 대응합니다. TEXT는 CLOB, DATETIME은 TIMESTAMP, NUMERIC은 DECIMAL로 변환하며 저장된 설계 타입은 유지합니다. 인용 식별자는 입력한 대소문자를 유지합니다. IDENTITY 개수·타입·DEFAULT, DECIMAL 자리수, LOB 키/인덱스, UNIQUE의 NULL 제약 등을 검사합니다. 새 컬럼의 기본 타입은 DB2 대상일 때 VARCHAR(255)입니다. 실제 DB2 연결 실행과 z/OS·IBM i 전용 문법은 지원하지 않으며 DB2 서버에서의 실행 검증은 별도로 필요합니다.

배포 빌드: `npm run build` 후 `npm start`.

설계 저장 DB는 `data/erd.sqlite`입니다. 설계의 SQL 생성 대상(DB2/SQLite/MySQL/PostgreSQL)과 앱의 저장 DB(SQLite)는 별개입니다. 1.2초 후 자동 저장되며 최근 30개 저장 이력을 복원할 수 있습니다. 브라우저 초안은 localStorage에 보관합니다. 다른 프로젝트로 전환하기 전 저장 버튼으로 저장 완료를 확인하세요.

테이블 추가 → 컬럼 편집 → 오른쪽 컬럼 연결점을 다른 테이블의 왼쪽 연결점으로 드래그하면 FK 관계가 생성됩니다. 관계선 더블 클릭으로 설정합니다. 컬럼의 ⋯ 메뉴에서 사전 연결, 기본값, UNIQUE, 삭제를 설정합니다. Ctrl+Z / Ctrl+Y로 편집 실행 취소·재실행, Ctrl+S로 저장합니다.

테이블 `메뉴 → 테스트 데이터 생성`에서 1~10000행의 INSERT SQL을 자동 생성합니다. 시작 번호, 자동증가 컬럼 포함 여부, 컬럼별 자동값·고정값·NULL·DB 기본값을 설정할 수 있습니다. 기본적으로 자동증가 컬럼을 제외하고 FK의 부모 데이터는 생성하지 않습니다. PK/UNIQUE 중복·숫자 범위·문자열 길이·NULL·날짜 형식을 검사하고 5행 미리보기, 편집, 복사, SQL 다운로드를 제공합니다. 데이터 생성은 SQL 출력만 수행합니다.

같은 팝업에서 엑셀 양식을 다운로드하거나 XLSX를 INSERT로 변환할 수 있습니다. `Test Data` 시트의 1~3행은 물리명·논리명·타입이며 4행부터 입력합니다. 4행 샘플을 수정하거나 삭제하세요. 빈 셀 / `[NULL]`은 NULL, `[DEFAULT]`는 DB 기본값입니다. 수식은 지원하지 않으며 큰 정수와 DECIMAL은 텍스트로 입력해야 자리수가 유지됩니다. 2MB, 10000행, 100000셀까지 지원합니다. 입력 셀을 SQL로 직접 실행하지 않고 타입에 맞게 변환·이스케이프합니다.

`메뉴 → 즐겨쓰는 SQL 예시`는 선택 테이블과 ERD 관계에 맞춘 백업/복원, SELECT, 페이징, INNER/LEFT JOIN, 부모별 자식 개수/마지막 행, DISTINCT/CASE/GROUP BY/날짜 통계, INSERT, UPDATE/DELETE, UPSERT를 제공합니다. DB2는 CTAS WITH DATA·FETCH NEXT·IDENTITY_VAL_LOCAL·MERGE를 사용합니다. 예시는 편집 후 현재/전체 복사 및 SQL 다운로드가 가능합니다. 실행할 값과 조건, 백업 이름은 사용 환경에 맞게 수정하세요. 실제 DB2 서버에서의 실행 검증은 별도로 필요합니다.

컬럼을 추가하면 논리명 입력란에 바로 입력할 수 있습니다. 논리명 또는 물리명이 입력 문자열을 포함하는 용어사전 항목을 제안하며 클릭 또는 ↑/↓ 후 Enter로 선택하면 논리명·물리명·타입·자리수를 함께 적용합니다. 일치 항목이 없어도 직접 입력할 수 있고, 사전 연결된 논리명을 수정하면 연결을 해제하여 입력값을 보존합니다. Esc로 제안을 닫습니다.

사전 버튼은 큰 관리 팝업을 엽니다. 단어·용어·타입 탭에서 표를 직접 편집하고 검색·정렬할 수 있습니다. 용어는 단어 조합 순서를 변경할 수 있으며 자리수와 소수 자리수를 지정하면 최종 타입이 미리 표시됩니다. 빈 자리수는 타입사전 기본값(기존 VARCHAR(45)처럼 괄호가 포함된 타입도 지원)을 사용합니다. INTEGER/TEXT/DATE 등은 자리수를 입력하지 않습니다. 변경 적용으로 연결된 컬럼에 일괄 반영하며 취소는 초안을 버립니다. 전체 적용은 한 번의 실행 취소로 복구됩니다. 사용 중인 항목 삭제는 참조를 안내한 뒤 연결을 해제하고 이름과 타입을 보존합니다. SQLite의 VARCHAR 길이와 DECIMAL 정밀도는 설계/SQL 표현이며 데이터 제약을 자동 생성하지 않습니다.

지원: 테이블/컬럼 편집, PK/자동 증가/NULL/UNIQUE/기본값, 단일 컬럼 FK, 관계 표시, 인덱스, 메모, 확대/축소/미니맵, 사전 동기화, 다크 모드, SQLite 저장/프로젝트/이력, JSON 가져오기·내보내기, 현재 화면 PNG, DB2/SQLite/MySQL/PostgreSQL DDL 생성.

Excel 버튼은 첨부 예시와 같은 전체 테이블 목록, 단어/용어/타입 사전, 테이블명 목록, 전체 컬럼 목록, 테이블별 상세 시트가 있는 XLSX를 내보냅니다. 용어별 자리수·소수 자리수와 최종 타입, PK/FK/NULL/기본값·인덱스를 포함합니다.

SQL 화면에서 생성 스크립트를 편집하거나 .sql 파일을 불러온 뒤 `SQL로 테이블 생성`을 누르면 새 SQLite 파일에 테이블과 인덱스를 생성합니다. 저장 위치는 `data/generated/<고유 ID>.sqlite`이며 ERD 저장 DB와 분리됩니다. 실행 실패 시 전체 작업을 취소하고 실패한 파일을 제거합니다. 테이블과 인덱스 생성만 지원하며 데이터 변경, ATTACH, DROP 등은 실행하지 않습니다. 생성 결과에서 SQLite 파일을 다운로드하거나 테이블·컬럼·관계·인덱스를 ERD로 가져올 수 있습니다. 기존 테이블과 이름이 겹치면 가져오기를 중단하며 실행 취소로 가져오기를 복구할 수 있습니다. SQL 실행 대상은 SQLite입니다. DB2/MySQL/PostgreSQL SQL은 출력만 지원합니다. Node.js 24.10 이상이 필요합니다.

초기 버전의 제한: 복합 FK 및 표현식 인덱스의 ERD 가져오기, 전체 캔버스 PDF, 수동 관계선 꺾임 편집은 아직 지원하지 않습니다. 관계 표기 선택은 표시용이며 1:1 UNIQUE와 식별 관계 PK는 컬럼에서 직접 지정합니다. 생성 SQL은 실행 전 검토하세요.

테이블 메뉴의 Java VO 생성은 카멜/파스칼/스네이크/대소문자/원래 이름, 접두어 제거, 클래스/패키지명, 래퍼/기본형, java.time/java.sql, 직접 getter/setter 또는 Lombok, 논리명 주석과 Serializable 옵션을 제공합니다. DECIMAL/NUMERIC/DECFLOAT은 BigDecimal, 바이너리는 byte[]로 변환합니다. 예약어는 밑줄을 붙이며 변환된 이름 충돌은 알려줍니다. 미지원 타입은 String이며 생성 소스를 수정·복사하거나 .java로 저장할 수 있습니다. Lombok 선택 시 대상 Java 프로젝트에 Lombok 설정이 필요합니다.

테이블 메뉴의 SQL XML 생성은 MyBatis Mapper XML을 생성합니다. VO 경로/Mapper namespace/VO와 같은 필드명 변환, resultMap, jdbcType, 자동증가·DB 기본값 컬럼 제외, NULL 건너뛰기 UPDATE, CRUD 선택, JDBC 또는 DB2 selectKey 자동키 반환을 지원합니다. 복합 PK 전체로 단건 조건을 만들며 PK가 없으면 WHERE 1 = 0을 사용합니다. 기본 키 반환은 꺼져 있습니다. 목록 조회는 조건 없으면 전체 조회이며 모든 수정값이 NULL인 선택적 UPDATE는 AND 1 = 0으로 변경을 차단합니다. VO 하나를 파라미터로 받는 MyBatis 메서드와 함께 사용하세요. 실제 MyBatis/DB2 연결 실행 검증은 별도 필요합니다.

프로젝트 메뉴 왼쪽 버튼으로 왼쪽 탐색 메뉴를 접거나 펼칠 수 있고 상태를 기억합니다. 용어사전에 연결되지 않았고 물리명으로도 일치하지 않는 컬럼은 주황색 테두리로 표시합니다. 컬럼 오른쪽 점 손잡이를 마우스로 끌어 원하는 행의 위/아래로 옮깁니다. Alt+↑/↓ 키보드 이동도 지원합니다. 이동은 실행 취소가 가능하며 PK/FK/인덱스 참조는 유지되고 저장 및 내보내기에도 순서가 반영됩니다.

헤더 SQL 메뉴: 1) ERD 전체 SQL OUT 2) SQL 읽어서 테이블 레이아웃 생성. 가져오기는 DB2 LUW DDL을 브라우저에서 분석하며 DB 실행 없이 단일/복수 테이블을 선택합니다. CREATE TABLE, ALTER TABLE ADD COLUMN/키 제약/ALTER COLUMN 타입·NULL·DEFAULT, COMMENT ON TABLE/COLUMN, 일반 CREATE INDEX를 지원합니다. 스키마 유지/제외, SQL 주석/사전 논리명 우선순위, 사전 연결, FK 관계 가져오기, FK/격자 배치, 기존 테이블 건너뛰기/갱신/이름 변경 옵션과 컬럼 변경 미리보기를 제공합니다. 기존 위치와 컬럼은 기본적으로 유지하며 삭제 옵션은 꺼져 있습니다. 적용 전체는 한 번에 실행 취소됩니다. UTF-8 및 EUC-KR/CP949 파일을 지원합니다. DB2의 비인용 식별자는 대문자로 해석하고 인용 식별자는 보존합니다. 사전 연결은 원래 SQL 식별자와 논리명을 바꾸지 않는 경우에 적용합니다. 스키마와 IDENTITY ALWAYS/BY DEFAULT 및 옵션은 SQL OUT에 보존됩니다.
복합 FK는 미리보기만 제공하며 관계선 가져오기는 단일 컬럼 FK만 지원합니다. 계산식 GENERATED, CREATE TABLE AS/LIKE, 표현식/DESC 인덱스, CHECK, 테이블스페이스/파티션 등 지원하지 않는 구문은 분석 알림으로 안내하며 원문 SQL의 모든 기능을 재현하거나 실행 검증하지 않습니다. 구문은 세미콜론으로 구분하세요.

앱을 열면 SQLite의 app_settings에 기록된 마지막 프로젝트를 복원합니다. 기록이 없거나 휴지통에 있으면 최근 저장한 활성 프로젝트를 선택합니다. 서버 문서보다 최신인 동일 프로젝트의 로컬 초안은 보존하며, 시작 문서 선택이 끝나기 전에는 자동 저장하지 않습니다. Excel 버튼에서 테이블 정의서 헤더 색상(프리셋/직접 선택/HEX)과 미리보기를 제공하며 프로젝트별 exportOptions.headerColor에 저장합니다. 밝기에 맞춰 글자색을 조정하고 테이블별/전체/사전/목록 헤더에 반영합니다. 컬럼 드래그는 같은 테이블 안에서만 가능하며, 놓을 때 한 번 적용하고 실행 취소로 복구합니다.

관계 연결점은 부모(오른쪽 원형)/자식(왼쪽 사각형)으로 구분하며 28px 반응 영역과 주변 스냅을 제공합니다. 드래그 또는 연결점 두 번 순차 클릭으로 연결할 수 있고, 연결 대상 컬럼을 강조합니다. 캔버스의 관계 연결 버튼에서는 테이블/컬럼을 직접 선택합니다. 연결 직후 설명 입력창을 열며, 기존 선이나 설명 라벨을 한 번 클릭해 설명·끝점·관계 표기를 수정할 수 있습니다. 설명은 1000자와 여러 줄을 지원하고 Ctrl+Enter로 저장하며 ERD 선에 표시합니다. 프로젝트 저장/복사/JSON에 유지되고 물리 SQL에는 영향을 주지 않습니다. 중복 관계와 같은 컬럼 자기 연결은 차단하며 같은 테이블 내 서로 다른 컬럼의 자기 참조는 가능합니다.

ERD 화면의 상단 헤더 색상 버튼과 각 테이블 헤더의 팔레트 버튼에서 화면 헤더 색상을 변경합니다. 선택 테이블 또는 프로젝트 전체에 적용하며, 전체 적용은 개별 색상을 초기화하고 새 테이블에도 이어집니다. 배경색에 따라 글자색을 자동 조정하고 프로젝트 저장·복사·JSON에 유지됩니다. Excel 정의서 색상 옵션과는 별도로 저장하며 실행 취소로 복구할 수 있습니다.

공용 사전: SQLite의 shared_words(단어), shared_terms(용어), shared_domains(도메인), shared_term_words(조합 순서)와 shared_dictionary_meta(버전)에 별도로 저장합니다. 사전 팝업에서 프로젝트 사전/공용 사전/통합 조회를 선택합니다. 단어·용어는 물리명 또는 논리명, 도메인은 이름이 일치하면(공백 정리·대소문자 무시) 프로젝트 정의가 우선합니다. 프로젝트 사전은 기존 JSON 구조에 유지하고 공용 정의는 프로젝트에 복제하지 않습니다.
프로젝트 사전을 공용 초안에 추가한 뒤 검토·적용할 수 있고, 기존 공용 중복 정의는 유지합니다. 통합 조회에서 공용 항목을 프로젝트에 재정의할 수 있습니다. 공용 변경은 연결된 모든 프로젝트를 하나의 트랜잭션으로 동기화하고 저장 이력을 남깁니다. 공용 항목 삭제는 현재 컬럼 값을 보존하며 연결을 해제하고, 남은 프로젝트 재정의는 유지합니다. 동시 변경은 버전 충돌로 차단합니다. 공용 참조는 프로젝트 복사에도 유지됩니다. 검색 제안·컬럼 설정·DB2 SQL 가져오기·Excel 사전에 통합 정의를 사용합니다.
기존 프로젝트 사전을 자동으로 공용으로 옮기지 않습니다. 공용 사전은 처음에는 비어 있습니다. 기존 폐쇄망 설치에 업데이트할 때 기존 data 폴더를 유지하면 시작 시 새 공용 테이블을 자동 생성합니다. 공용 사전 백업도 data/erd.sqlite에 포함됩니다.
